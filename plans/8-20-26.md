## TL;DR

`@putervision/world-model-mcp` is a robust, local-first MCP server (~9,718 lines of TS, 21 MCP tools, 21 CLI commands, 29 test files, and only 3 runtime dependencies). The core architecture is sound, featuring SQLite WAL mode, connection caching with LRU eviction, full-text FTS5 search, graceful shutdown handlers, and SHA-256 tamper-evident event chains.

The primary improvement areas identified and prioritized are:

1. **Thin documentation** — `concepts.md` (17 lines), `configuration.md` (9 lines), `features.md` (12 lines), and `codebase-distillation.md` (19 lines) are stubs and need expansion with diagrams and full parameter specifications. Also fix the env var naming discrepancy (`LOG_LEVEL` vs `WORLD_MODEL_MCP_LOG_LEVEL`) in `docs/configuration.md`.
2. **CI/CD hardening** — `npm run lint` is currently **missing from the CI workflow** (present in `npm run ci` script but omitted in `.github/workflows/ci.yml`), `npm audit` is absent, `publish.yml` lacks pre-publish test verification, and Dependabot is not configured.
3. **Security edge cases** — Dead code in `path-validator.ts`, empty-slug fallback in `sanitizeSlug()`, custom schema layer input size caps, and recursion depth caps in `redactData`.
4. **Usability & CLI flags** — Add `--port`, `--host` (gated behind `--insecure`), `--verbose`, `--quiet`, and `--json` (for `inspect`) CLI flags.
5. **Developer Experience & Tooling** — Add `.editorconfig`, pre-commit hooks (`lint-staged`), coverage thresholds in `vitest.config.ts`, and runnable examples.

## 1. Security

### 1.1 Path Validator Dead Code
- **File:** `src/utils/path-validator.ts` (lines ~36–40)
- **Issue:** The block `if (normalized.includes('..') && !path.isAbsolute(filePath))` has an **empty body**. While the downstream `allowed.some(...)` check safely restricts access, the dead block is misleading.
- **Fix:** Remove the dead block and add a unit test explicitly asserting that relative traversal paths (e.g. `../etc/passwd`) resolving outside `allowedExportDirs` throw `ValidationError`.

### 1.2 Empty Slug Edge Case
- **File:** `src/engine/db.ts` → `sanitizeSlug()`
- **Issue:** `sanitizeSlug("")` returns `""`. Downstream calls like `path.join(baseDir, "")` resolve to `baseDir` itself, which could inadvertently read/write the base directory.
- **Fix:** Guard `sanitizeSlug`: if the sanitized string is empty, throw a `ValidationError` or return a safe default fallback like `"default"`.

### 1.3 Input Size Caps in Custom Schema Layer
- **File:** `src/schema/schemas.ts` and `src/tools/handlers.ts`
- **Issue:** Hand-rolled schema classes (`ObjectSchema`, `StringSchema`, `ArraySchema`) lack explicit byte/element size caps. Malicious or malformed client payloads could cause excessive memory consumption.
- **Fix:** Add `maxBytes` / `maxLength` validation methods to `src/schema/schemas.ts` and enforce a maximum payload limit (e.g. 1 MB) before invoking handlers.

### 1.4 Redaction Coverage
- **File:** `src/utils/redact.ts`
- **Issue:** Missing redaction regex patterns for JWT tokens (`eyJ...`), AWS session tokens (`ASIA...`), and generic 64-character hex secret strings.
- **Fix:** Add regex patterns for JWTs, AWS session tokens, and long hex strings. Add a unit test suite testing a corpus of secret formats.

### 1.5 npm Audit in CI
- **File:** `.github/workflows/ci.yml` and `.github/workflows/publish.yml`
- **Issue:** No automated vulnerability auditing in CI workflows.
- **Fix:** Add `npm audit --audit-level=high` step to both `ci.yml` and `publish.yml`.

### 1.6 SECURITY.md Expansion
- **File:** `SECURITY.md` (23 lines)
- **Issue:** Brief overview without a formalized threat model or vulnerability disclosure timeline.
- **Fix:** Add sections detailing the local-first trust boundary, absence of network egress, stdio transport isolation, and vulnerability triage SLAs.

### 1.7 What's Already Good (Security)
- `view` HTTP server binds strictly to `127.0.0.1` (`src/cli/commands/view.ts` line 336) — no LAN exposure.
- `path-validator.ts` enforces `allowedExportDirs` boundaries.
- `redact.ts` scrubs passwords, API keys, and bearer tokens from logs and diagnostics.
- `sanitizeSlug()` strips path traversal symbols.
- Root `package.json` pins vulnerable transitive dependencies via `overrides`.
- SHA-256 event chaining ensures tamper-evident operation logging.
- Strictly local-first architecture with zero telemetry.

## 2. Performance

### 2.1 Query Row Limits & Pagination
- **File:** `src/engine/entity-store.ts`, `src/engine/spatial-graph.ts`, `src/engine/export.ts`
- **Issue:** `exportWorldModel` and full-graph spatial relation queries could produce large memory allocations in massive scenes (10,000+ entities).
- **Fix:** Enforce a default `MAX_ROWS` (e.g. 10,000) for list and export queries with a `truncated: true` indicator when exceeded.

### 2.2 `redactData` Recursion Depth Cap
- **File:** `src/utils/redact.ts`
- **Issue:** `redactData` recursively traverses nested objects and arrays without a depth limit, creating a potential stack-overflow risk for deeply nested objects.
- **Fix:** Add a `maxDepth = 32` recursion limit to `redactData`.

### 2.3 DB Connection Cache & Eviction — ✅ Verified & Handled
- **Status:** Already implemented in `src/engine/db.ts`:
  - `MAX_CACHED_DBS = 5` enforced for both read-write (`dbCache`) and read-only (`readOnlyDbCache`) pools.
  - `closeAllDbs()` is implemented (line 262) and invoked by the shutdown handler in `src/index.ts`.

### 2.4 Export Pagination & Streaming
- **File:** `src/engine/export.ts`
- **Issue:** glTF, OBJ, and JSON exports serialize the full graph into memory at once.
- **Fix:** Add optional `limit` and `offset` filtering to `get_spatial_map` and export tools.

### 2.5 SQLite Pragmas & Concurrency — ✅ Verified & Handled
- **Status:** Already configured in `src/engine/db.ts` (lines 174–180):
  - `journal_mode = WAL`, `synchronous = NORMAL`, `busy_timeout = 5000` (via `WORLD_MODEL_BUSY_TIMEOUT_MS`).
  - `foreign_keys = ON`, `cache_size = -20000` (20 MB cache), `mmap_size = 128 MB`, `trusted_schema = OFF`.
  - Read-only connections enforce `query_only = ON` and `enable_load_extension = 0`.
